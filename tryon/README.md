# 试衣间 · Try-On Prototype

网购时把衣服图片**拖一下就穿到自己身上**，可以多件叠搭，还能根据尺码表判断**合不合身**。

```
tryon/
├── extension/                  Chrome 插件（MV3），直接“加载已解压的扩展程序”
│   ├── manifest.json
│   ├── background.js           右键菜单 / 工具栏 → 侧边栏
│   ├── content.js              购物页面：悬停“试穿”按钮、拖拽投放区、页内浮动面板
│   └── studio/                 试衣间主界面（插件侧边栏、页内面板、网页版共用）
│       ├── studio.html/css/js  叠搭画布、衣橱、身体数据、AI 渲染
│       ├── extract.js          从商品页提取标题/价格/主图（JSON-LD / OpenGraph / 大图）
│       ├── imaging.js          纯色背景抠图、按类别自动摆放、合成
│       ├── fit.js              尺码表解析 + 合身度判断 + 尺码推荐
│       └── samples/            示例模特和单品（零素材也能体验）
└── server/                     零依赖 Node 服务（Node ≥ 18）
    ├── server.mjs              静态托管 + 商品页/图片代理 + /api/tryon
    ├── providers.mjs           Gemini / FASHN / 自部署开源模型 / Mock
    └── .env.example
```

## 快速开始

```bash
cd tryon
cp server/.env.example server/.env    # 可选：填 GEMINI_API_KEY 或 FASHN_API_KEY
node server/server.mjs                # 打开 http://localhost:8787
```

不填任何 Key 也能用：叠搭预览、抠图、尺码推荐都在浏览器本地完成；「AI 真实上身」会走 Mock（直接返回叠搭预览图），用来跑通流程。

**装插件：** Chrome 打开 `chrome://extensions` → 打开「开发者模式」→「加载已解压的扩展程序」→ 选 `tryon/extension`。

装好后在任意购物网站：

| 操作                                 | 效果                                             |
| ------------------------------------ | ------------------------------------------------ |
| 鼠标悬停在商品大图上 → 点「👗 试穿」 | 加入衣橱并直接穿上，右侧滑出试衣间面板           |
| 拖动任意图片                         | 右侧出现「松手就穿上」投放区，松手即试穿         |
| 右键图片 →「👗 试穿这件」            | 同上                                             |
| 右下角 👗 按钮 / 工具栏图标          | 打开页内面板 / 侧边栏                            |
| 在面板里粘贴商品链接                 | 插件直接抓取商品页（带你的登录态），选一张图穿上 |

插件从当前页面顺带读出商品标题、价格、类别（上衣/外套/下装/鞋…），自动决定放在身上哪个位置和哪一层。

## 需要你提供的素材

**必需**

1. **一张全身照（最重要）**：正面站直、头顶到脚底完整入镜、手臂稍微离开身体、穿贴身素色衣服（紧身 T 恤 + 紧身裤最好）、背景干净、光线均匀，长边 ≥ 1024px。可以多拍几张不同姿势（正面 / 侧身 / 手插兜），在「我的」里切换。
2. **商品图**：插件会自动抓。效果排序：白底平铺图 > 白底挂拍图 > 模特上身图。前两种本地抠图就能很好地叠搭预览；模特图的预览会带背景，但 AI 渲染不受影响。

**判断合不合身（强烈建议）**

3. **身体数据（cm/kg）**：身高、体重；最好再量胸围、腰围、臀围、肩宽。只填身高体重时会粗略估算，误差比较大。
4. **偏好**：修身 / 常规 / 宽松。
5. **商品尺码表**：从商品详情页复制粘贴进单品详情（第一行表头，如 `尺码 胸围 衣长 肩宽`，后面每行一个尺码）。支持“平铺宽度”的表，会自动 ×2 换算成围度。

**可选，用于以后提升效果**

6. 一两件你**已有、穿着合身的衣服**的实测尺寸：用来校准你自己的“合身偏好”，比通用规则准。
7. 想用哪个 AI 引擎、以及对应的 API Key（见下）。

隐私：照片和衣橱只存在你本机浏览器里（插件存在 `chrome.storage`，网页版存在 IndexedDB），只有点「AI 真实上身」时才会把照片发给你配置的服务。

## 两层效果：叠搭预览 + AI 真实上身

1. **叠搭预览（本地、即时、免费）**：抠掉商品图的纯色背景，按类别放到身体对应位置（人体框可调），按 内层→外层 叠放。每件都能拖动、缩放（右下角手柄 / 滚轮）、旋转（顶部手柄）、上下调层、隐藏。用来快速试颜色和搭配。
2. **AI 真实上身**：把你的照片和当前搭配（按内→外顺序）发给后端模型，生成真实的上身图，包括褶皱、光影和版型。叠搭预览图也会作为“摆放参考”一起发过去，所以你在画布上调的层次会被尊重。

| 引擎                 | 叠搭方式                           | 支持品类               | 说明                                                          |
| -------------------- | ---------------------------------- | ---------------------- | ------------------------------------------------------------- |
| `gemini`（推荐起步） | 一次调用穿整套                     | 全部（含鞋、包、帽子） | `GEMINI_API_KEY`；模型名可用 `GEMINI_IMAGE_MODEL` 改          |
| `fashn`              | 逐件链式叠加（上一步结果当模特图） | 上衣 / 下装 / 连衣裙   | 专用试穿模型，衣服细节（logo、印花）保留最好；`FASHN_API_KEY` |
| `selfhost`           | 逐件链式叠加                       | 上衣 / 下装 / 连衣裙   | 自己的 GPU 上跑开源模型，`SELFHOST_URL`，接口约定见下         |
| `mock`               | —                                  | —                      | 不调用模型，测流程                                            |

自部署接口约定（给 CatVTON / IDM-VTON / Leffa 包一层 FastAPI 即可）：

```
POST $SELFHOST_URL
{ "person": "data:image/jpeg;base64,...", "garment": "data:image/jpeg;base64,...", "category": "upper" | "lower" | "overall" }
→ { "image": "data:image/png;base64,..." 或 "https://..." }
```

## 现有开源项目调研 & 为什么这样设计

**试穿模型（核心生成能力）**

- **CatVTON**、**IDM-VTON**、**Leffa**、**OOTDiffusion**、**StableVITON**：都是单件试穿（上/下/连衣裙），需要 GPU，许可证多为非商用（CC BY-NC 类，商用前要逐个确认）。其中 CatVTON 轻量、易部署，适合作为自部署首选。
- **OmniTry**：支持帽子、包、首饰等“任意可穿戴物”，但仍是一次一件。
- **Any2AnyTryon**、**OmniVTON / OmniVTON++**：后者是免训练的方法，支持多件。
- 2026 年的研究（Garments2Look 数据集、Layering Virtual Try-On 等）专门指出：**整套搭配和正确的层次关系是目前开源模型的短板**，常见做法是逐件串联，或者用文字指令描述层次。

**插件类**

- `rishiskhare/virtual-try-on`：Chrome 插件，从网页把衣服图拖进侧边栏，后端用 fal.ai。
- `jbilcke-hf/atryon`：免费 Chrome 插件 + 独立后端。
- `shyjal/visual-try-on`：上传人像 → 打开商品页 → 点 Try On。

这些项目验证了“插件 + 侧边栏 + 云端模型”这条路可行，但都是**单件试穿**，也**不管尺码合不合身**。

**所以这个原型的取舍：**

1. 生成模型做成可插拔的 provider：先用 Gemini 或 FASHN API 快速验证体验；量大了或者在意隐私时，换成自部署的 CatVTON / IDM-VTON，前端不用改。
2. 叠搭由我们自己的“搭配层”负责：本地画布决定层次和位置 → 单件模型按内→外链式调用，多图模型一次调用并附上叠搭参考图。这正好补上开源模型的短板。
3. “合不合适”拆成两个问题：**好不好看**交给生成图回答，**尺码合不合身**交给尺码表和身体数据回答。生成模型无法判断尺码，硬让它“画出偏紧的效果”是不可靠的。

## 已知限制 / 下一步

- 本地抠图只处理纯色背景。下一步可以把 `@imgly/background-removal` 或 MediaPipe 的分割模型打包进插件（MV3 不允许远程代码，必须打包到本地）。
- 自动摆放用的是可调“人体框”加上经验比例。接入 MediaPipe Pose 自动找肩、腰、脚踝后会准很多。
- 淘宝、京东等站点反爬严格，服务器端的链接解析经常失败。插件模式在你已打开的页面里直接读 DOM，不受影响，所以推荐用插件。
- 尺码判断是基于“放松量”的规则，没有考虑面料弹性。可以用你自己合身衣服的数据（素材第 6 条）做个性化校准。
- 还没做：尺码表自动抓取（各站结构不同，需要逐站适配）、结果历史 / 对比、移动端 App 壳（studio 是响应式网页，可以直接套 Capacitor 或 PWA）。
